> 文档版本：v1.0
> 状态：待评审 / 待开发
> 适用范围：婚礼仪式智能体后端（`backend/`）
> 关联文档：`.agent/1.鉴权设计与处理/需求分析.md`、`.agent/鉴权/需求.md`、`backend/docs/ARCHITECTURE.md`

## 1. 背景与现状

当前 `backend/` 已具备：

- **Web 层**：FastAPI 应用工厂（`app/main.py`），路由聚合于 `app/api/v1/router.py`，统一前缀 `/api/v1`。
- **数据层**：异步 SQLAlchemy（`app/core/database.py`，SQLite + aiosqlite），`Base` 元数据自动建表。
- **协议层**：共享 Pydantic Schema 位于 `shared/schemas/`，避免 `app/` 与 `agent/` 循环依赖。
- **业务编排层**：`app/services/`，如 `ChatService` 作为 API 与 Agent 的桥梁。
- **Agent 层**：与 Web 解耦，`agent/agents/base_agent.py` 定义抽象基类 `BaseAgent`（必须实现 `async def run(input_text, state, **kwargs)`），`CoordinatorAgent` 等子类通过 `state`/`**kwargs` 透传上下文（如 `memory`）。

**缺失能力**：

1. 无用户体系、无登录入口。
2. 无 JWT 签发 / 校验机制（`ARCHITECTURE.md` 已预留 `app/core/security.py` 但未实现）。
3. 接口未做鉴权，任意调用方均可访问。
4. Agent 层无法感知"当前是谁在调用"，无法在 `context` 中携带鉴权 token、在状态中携带用户信息。

本需求的目标：在不破坏「Web 层与 Agent 层解耦」原则的前提下，建立一套**基于 JWT 的鉴权链路**，使：

- 用户可登录并获取 token；
- 受保护接口必须携带有效 token；
- FastAPI 校验通过后，将 **token** 与 **用户信息** 暂存；
- 创建 Agent 时，能从暂存区读取 **token（经 context）** 与 **用户信息（经 AgentState）** 注入到 Agent 运行时。

## 2. 需求拆解与验收标准

| 编号 | 需求（来自需求分析） | 技术实现要点 | 验收标准 |
|------|----------------------|--------------|----------|
| 1 | 模拟公共用户信息表 JSON 数据（实际开发用数据库） | 提供 `users_mock.json`，结构对齐后续 ORM 模型；封装读取函数 | 可加载到内存，按 `username` 查询用户 |
| 2 | 创建 FastAPI 用户模块，登录接口，引入 JWT，签发 token | `app/api/v1/user.py` + `core/security.py`（JWT 签发/校验） | `POST /api/v1/user/login` 返回 `access_token` |
| 3 | 封装消息模块：发送消息、删除消息接口 | `app/api/v1/message.py` + `MessageService` + 消息 Schema | `POST /message` 与 `DELETE /message/{id}` 可用且受保护 |
| 4 | 接口需携带授权 token；FastAPI 鉴权后将 token 及用户信息存起来 | 鉴权依赖 `get_current_user`，写入 `request.state` 并注入 context | 未带/带错 token 返回 401；正确时下游可取到 user |
| 5 | 创建 Agent 时查询 token 及用户信息，参考 `agent/agents/base/base.py` | token 经 `contextvars` 存储；用户信息经 `AgentState`/`run` 的 kwargs 传入 | Agent 运行期可读取当前 token 与 user 信息 |

> 需求 5 与 `.agent/鉴权/需求.md` 完全对齐：
> - **鉴权 token 通过 context 存储** → 采用 `contextvars.ContextVar`，在请求生命周期内异步安全传播。
> - **用户信息通过 AgentState 存储** → 定义 `AgentState`，随 `agent.run(..., state=...)` 透传。

## 3. 总体设计

### 3.1 鉴权数据流

```
┌────────────┐   username/password    ┌──────────────────┐
│   Client   │ ──────────────────────▶│  POST /user/login│
└────────────┘                        └────────┬─────────┘
                                              │ 校验 mock 用户
                                              │ 签发 JWT
                                              ▼
                                        { access_token }
                                              │
┌────────────┐  Authorization: Bearer <token> ┌──────────────────┐
│   Client   │ ─────────────────────────────▶│ Depends(get_current_user)
└────────────┘                                │  1. 解析 JWT
                                              │  2. 查用户
                                              │  3. 写入 request.state
                                              │  4. 注入 contextvars
                                              ▼
                                   ┌──────────────────────┐
                                   │ 受保护路由 / Service   │
                                   │ 创建 Agent 时：        │
                                   │  - token ← contextvar  │
                                   │  - user  ← AgentState  │
                                   └──────────┬───────────┘
                                              ▼
                                   ┌──────────────────────┐
                                   │  agent.run(input,      │
                                   │    state=AgentState)   │
                                   └──────────────────────┘
```

### 3.2 设计原则（延续 `ARCHITECTURE.md`）

1. **Web 与 Agent 解耦**：Agent 不直接依赖 `Request` 或 FastAPI。token 通过 `contextvars` 注入，用户信息通过 `AgentState` 注入，Agent 运行期零 HTTP 依赖。
2. **配置集中**：JWT 密钥、算法、过期时间统一在 `app/core/config.py` 读取。
3. **模拟先行**：用户数据先以 JSON 模拟，封装为可替换的数据访问函数，后续替换为 ORM 查询时无需改动上层。
4. **最小侵入**：复用现有 `services/` 编排模式与 `shared/schemas/` 协议层。
5. **横切状态模块化**：鉴权 token / 用户信息作为 Agent 的横切状态，应以独立模块（`agent/context.py`、`agent/state.py`）创建，既不耦合具体 Agent，也不耦合 Web 框架（详见 §3.4）。

### 3.4 state 与 context 的模块化创建（重点）

鉴权在 Agent 层的落地依赖两类「横切状态」，为避免与具体 Agent 实现、Web 框架耦合，**必须以独立模块的形式创建**，而不是散落在各 Agent 或路由代码中：

| 模块 | 路径 | 职责 | 模块化理由 |
|------|------|------|------------|
| 鉴权上下文 | `agent/context.py` | 用 `contextvars` 在请求 / Agent 运行生命周期内传播 token 与 user | 与 HTTP 解耦，CLI / 定时任务 / 测试均可复用；协程级异步安全 |
| Agent 状态 | `agent/state.py` | 定义 `AgentState`，随 `agent.run(state=...)` 显式透传 user / token / metadata | 状态结构集中定义，所有 Agent 共用同一契约，扩展字段不破坏签名 |

模块化要点：

1. **独立文件、独立职责、独立测试**：`context` 与 `state` 均为 `agent` 包层级的一等模块，各自有明确边界，可单独单测。
2. **职责互补不重复**：`context` 负责「运行期隐式传播」（协程级），`state` 负责「运行期显式传参」（函数级）；前者解决"任意位置取得到"，后者解决"Agent 入参清晰"。
3. **装配便捷**：`AgentState` 提供 `from_context()` 工厂，从 `context` 一键装配，降低 Service 层接入成本。
4. **依赖单向无环**：二者被 `agent/` 与 `app/` 共用，相关类型（`UserInfo` 等）统一放在 `shared/schemas/`，保证依赖方向单一、无循环引用。
5. **可演进**：后续动态提示词、工具鉴权（ToolGuard）均在此两模块基础上扩展，不侵入具体 Agent。

> 对应需求 5：「鉴权 token 通过 context 存储」「用户信息通过 AgentState 存储」——本章即落实这两条的模块化组织方式。

### 5.2 JWT 工具（`app/core/security.py` 新增）

职责：

- `create_access_token(subject: str, extra: dict | None = None) -> str`：用 `JWT_SECRET`/`JWT_ALGORITHM` 签发，payload 含 `sub=username`、过期时间。
- `decode_access_token(token: str) -> dict`：校验签名与过期，失败抛 `JWTError`。
- `verify_password(plain: str, hashed: str) -> bool`：模拟阶段直接相等比较；DB 阶段用 `passlib` 校验哈希。

### 5.3 用户 Schema（`shared/schemas/user.py` 新增）

```python
class LoginRequest(BaseModel):
    username: str
    password: str

class TokenResponse(BaseModel):
    access_token: str
    token_type: str = "bearer"
    expires_in: int

class UserInfo(BaseModel):
    id: int
    username: str
    nickname: str
    role: str
```

### 5.4 登录接口（`app/api/v1/user.py`）

- 路径：`POST /api/v1/user/login`
- 入参：`LoginRequest`
- 逻辑：`UserService.authenticate(username, password)` → 成功则 `create_access_token(sub=username)` → 返回 `TokenResponse`。
- 失败：`HTTP 401`，`detail="invalid_username_or_password"`。

## 7. 鉴权依赖与上下文暂存

### 7.1 鉴权依赖（`app/deps.py` 新增）

```python
from fastapi import Depends, HTTPException, status, Request
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer
from app.core.security import decode_access_token
from app.services.user_service import UserService

bearer_scheme = HTTPBearer(auto_error=False)

async def get_current_user(
    request: Request,
    creds: HTTPAuthorizationCredentials | None = Depends(bearer_scheme),
) -> UserInfo:
    if creds is None or not creds.credentials:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "missing_token")
    try:
        payload = decode_access_token(creds.credentials)
    except Exception:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "invalid_or_expired_token")

    user = await UserService().get_by_username(payload["sub"])
    if user is None:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "user_not_found")

    # 需求 4：鉴权通过后将 token 及用户信息"存起来"
    request.state.token = creds.credentials
    request.state.user = user
    # 注入 contextvars，供解耦的 Agent 层读取（需求 5）
    set_auth_token(creds.credentials)
    set_auth_user(user)
    return user
```

> 路由上直接 `user: UserInfo = Depends(get_current_user)` 即为受保护接口；未带/非法 token 自动 401。

### 7.2 鉴权 Context（模块化模块：`agent/context.py`）

独立模块，详见 §3.4。用于"鉴权 token 通过 context 存储"，异步安全、与请求生命周期绑定，**不依赖 FastAPI**：

```python
from contextvars import ContextVar
from typing import Optional
from shared.schemas.user import UserInfo

auth_token_var: ContextVar[Optional[str]] = ContextVar("auth_token", default=None)
auth_user_var: ContextVar[Optional[UserInfo]] = ContextVar("auth_user", default=None)

def set_auth_token(t: str) -> None:
    auth_token_var.set(t)

def get_auth_token() -> Optional[str]:
    return auth_token_var.get()

def set_auth_user(u: UserInfo) -> None:
    auth_user_var.set(u)

def get_auth_user() -> Optional[UserInfo]:
    return auth_user_var.get()
```

## 8. Agent 鉴权数据注入（需求 5）

### 8.1 AgentState 定义（模块化模块：`agent/state.py`）

独立模块，详见 §3.4。用于"用户信息通过 AgentState 存储"：

```python
from dataclasses import dataclass, field
from typing import Any
from shared.schemas.user import UserInfo

@dataclass
class AgentState:
    user: UserInfo | None = None
    token: str | None = None
    metadata: dict[str, Any] = field(default_factory=dict)
```

### 8.2 BaseAgent 改造（`agent/agents/base_agent.py`）

将用户信息/鉴权上下文作为标准参数，向下透传（抽象基类已迁移至 `base_agent.py`，`base/` 作为正式包对外导出）：

```python
from abc import ABC, abstractmethod
from typing import Any
from agent.state import AgentState

class BaseAgent(ABC):
    name: str = ""
    description: str = ""

    @abstractmethod
    async def run(self, input_text: str, state: AgentState | None = None, **kwargs: Any) -> str:
        raise NotImplementedError
```

### 8.3 以 `agent/agents/base/base.py` 为例创建 Agent（参考实现）

> 注意：原项目存在 `agent/agents/base.py`（文件）与 `agent/agents/base/`（目录）同名遮蔽，`base/base.py` 无法被 import。本实现将抽象基类迁移至 `agent/agents/base_agent.py`，`base/` 成为正式包（`__init__.py` 导出 `BaseAgent` 与 `WeddingBaseAgent`），并修正原 `class BaseAgent(BaseAgent)` 同名遮蔽问题、重命名为实现类 `WeddingBaseAgent`。

```python
import os
from typing import Any
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage

from agent.agents.base import BaseAgent
from agent.state import AgentState
from agent.context import get_auth_token, get_auth_user

SYSTEM_PROMPT = "可咨询任何婚礼相关问题"

class WeddingBaseAgent(BaseAgent):
    name = "Base"
    description = "婚礼策划工程师"

    def __init__(self) -> None:
        model = init_chat_model(
            model="xopkimik26",
            model_provider="openai",
            base_url=os.getenv("XUNFEI_BASE_URL"),
            api_key=os.getenv("XUNFEI_API_KEY"),
        )
        self._agent = create_agent(model=model, system_prompt=SYSTEM_PROMPT)

    async def run(self, input_text: str, state: AgentState | None = None, **kwargs: Any) -> str:
        # 需求 5：从 context 取 token，从 AgentState 取用户信息
        token = state.token if state else get_auth_token()
        user = state.user if state else get_auth_user()

        # 可在此处将 user / token 注入 Prompt 或工具鉴权（对接 .agent/鉴权/需求.md 的动态提示词与工具鉴权）
        sys_prompt = SYSTEM_PROMPT
        if user:
            sys_prompt += f"\n当前用户：{user.nickname}({user.username})"

        res = await self._agent.ainvoke({"messages": [HumanMessage(input_text)]})
        return res["messages"][-1].content
```

### 8.4 Service 层注入（以消息/对话为例）

## 11. 关键流程时序

### 11.1 登录签发 token

```
Client → POST /user/login {username,password}
UserService.authenticate → 比对 mock 用户
security.create_access_token(sub=username)
→ {access_token, token_type, expires_in}
```

### 11.2 受保护接口鉴权 + 上下文暂存

```
Client → POST /message + Authorization: Bearer <token>
get_current_user:
  解析 JWT → 查用户 → 写 request.state.{token,user}
  注入 contextvars(auth_token_var, auth_user_var)
MessageService.create(user_id=user.id)
```

### 11.3 创建 Agent 注入鉴权数据

```
Service 组装 AgentState(user=current_user, token=get_auth_token())
agent.run(input_text, state=state)
  → Agent 内部读取 state.user / state.token
  → 可注入动态提示词 / 工具鉴权
```

## 12. 测试要点

1. **登录**：正确账号密码返回 token；错误密码 `401`。
2. **JWT**：过期 token 被拒；篡改 token 被拒；不同 `sub` 解析正确。
3. **受保护接口**：无 token → `401`；合法 token → 正常；token 与 `request.state` 一致。
4. **context 传播**：在 `agent.run` 内能取到 `AgentState.user` 与 `auth_token_var`。
5. **消息权限**：删除他人消息 → `403`；删除本人 → 成功。
6. **解耦校验**：Agent 单测不依赖 FastAPI `Request`，直接传 `AgentState` 即可运行。
